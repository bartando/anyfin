# CFF fonts bake with missing strokes (embeddedReact cf5dfe4, `bridges/quickjs/js/assets/rasterize.mjs`)

Run: `node cff-closepath.mjs [font ...]`. It mirrors bakeGlyph's 4 bpp call (ss 4, steps max(6, ceil(px/3)), baseline from the ascender) at 54 px. It prints ink % per glyph as baked, then again with every contour closed.

`flattenCommands` (line 33) is documented as returning "closed contours", but it only closes one when the path has an explicit `Z` (line 80). opentype.js emits no `Z` for either outline format here. glyf (TTF) contours happen to end on their start point, so nothing is lost. CFF contours end one point short (e.g. `l` = `M(10.5,10.7) L(3.6,10.7) L(3.6,50) L(10.5,50)`). The edge loop at line 146 (`for (i = 0; i + 1 < ct.length; i++)`) doesn't wrap last→first, so the closing edge is dropped and the nonzero scanline fill goes wrong: `l`/`I` come out 0% ink and `r` 2%, against 86/89/49% once closed. The closepath belongs where an open contour gets committed, which happens in two places: the `M` branch (line 42, before `contours.push(cur)`) and the after-loop push (line 88). Both should append `{x: sx, y: sy}` when the last point isn't already the start. Equivalently, wrap the edge loop to `i < ct.length` with `ct[(i + 1) % ct.length]`, which costs nothing for contours that are already closed. Nothing warns at bake time or at runtime. Workaround: ship TTF (glyf) fonts, e.g. `fonttools varLib.instancer InterVariable.ttf wght=600 opsz=drop`.
